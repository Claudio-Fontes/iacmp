# FAQ — Frequently Asked Questions

---

**Do I need to compile the TypeScript before running `iacmp synth`?**

No, as long as `tsx` is available in the project. `iacmp init` adds it
as a devDependency and `iacmp synth` registers it automatically to run
`.ts` directly (looking in parent directories as well, useful in monorepos). If
no `tsx` is found, the synth warns and skips the `.ts` stacks; in that case
run `npm i -D tsx` in the project. `.js` stacks (already compiled) are always
supported.

---

**Can I use iacmp without an AI API key?**

Yes — the entire CLI (`init`, `synth`, `deploy`, `destroy`, `diff`, `diagram`,
`audit-all`, `doctor`, `dashboard`, `registry`, `watch`) works without any
key. API keys (`ANTHROPIC_API_KEY`/`OPENAI_API_KEY`) only come into play for AI
generation (`iacmp ai`, `from-diagram`), which is part of **iacmp Pro**.

---

**What is iacmp Pro?**

AI generation backed by a corpus of examples in which every pattern was validated in
real deploys across all three clouds. The open CLI works 100% without it — the Pro
commands (`iacmp ai`, `from-diagram` and the example search in the MCP) simply report its
absence with a clear message.

---

**Does iacmp work with Claude Code?**

Yes, out of the box. `iacmp setup` registers the embedded MCP server in Claude Code
and Claude Desktop — the agent gains the `write_stack`,
`synth_project`, `deploy_project`, `destroy_project`, `validate_stack` and
`read_synth_output` tools (all local, no AI). With iacmp Pro, the MCP adds
`search_examples`/`list_examples` (search over the validated corpus). Without MCP, the
CLAUDE.md generated by `iacmp init` instructs the agent to use the CLI directly.

---

**Does iacmp perform real deploys?**

Yes. `iacmp deploy` calls the provider's native tooling under the hood —
`aws cloudformation package`+`deploy` (AWS), `az stack group create` (Azure),
`terraform apply` (GCP and `--format tf`). Function code packaging
(`Fn.Lambda`) happens at deploy time for all three clouds: esbuild of the handler with the
`@iacmp/runtime` facade resolved to the target cloud's adapter. Prerequisites:
the native CLI installed and authenticated (`iacmp doctor` checks; `--fix` installs) and
a synth done beforehand. Use `--dry-run` to see the exact commands without executing.

---

**Where do the generated templates live?**

In `synth-out/<provider>/` at the project root:
- AWS: `synth-out/aws/<stack>.json` (CloudFormation)
- Azure: `synth-out/azure/<stack>.bicep` + `_main.bicep` (single deployment)
- GCP: `synth-out/gcp/<stack>.tf.json` + `_providers.tf.json` (Terraform)
- `--format tf`: `synth-out/aws-tf/` and `synth-out/azure-tf/`

The per-provider subfolder keeps one output from overwriting another.

---

**How do I change a project's provider?**

Edit the `provider` field in `iacmp.json`:
```json
{ "provider": "azure" }
```

Or use the `--provider` flag per command:
```bash
iacmp synth --provider gcp
iacmp deploy --provider azure
```

The flag overrides the `iacmp.json` value for that run. To generate
Terraform for AWS/Azure, use `--format tf` (Terraform is an output format, not
a standalone provider).

---

**Can I have multiple stacks in the same project?**

Yes — and it is the convention: one stack per domain (network, data, compute…), linked
by cross-stack `ref()`. `iacmp synth` processes them all and resolves the
references; `deploy` orders them by dependency.

```
stacks/
├── network/api-stack.ts
├── compute/fn-stack.ts
└── database/db-stack.ts
```

---

**How do I create a custom provider?**

Use the `@iacmp/plugin-sdk`:

```javascript
const { definePlugin } = require('@iacmp/plugin-sdk');

module.exports = definePlugin({
  providers: [{
    name: 'meu-provider',
    synthesize(stack) {
      return { /* native template */ };
    },
  }],
});
```

Publish it to npm and add it to `iacmp.json`:
```json
{ "plugins": ["meu-pacote-plugin"] }
```

---

**How do I update iacmp?**

```bash
npm update -g iacmp
iacmp --version
```

---

**Does `iacmp watch` work with any provider?**

Yes. When it detects changes in `stacks/`, watch runs `iacmp synth` with the
provider from `iacmp.json`. Use `--provider` to override:
```bash
iacmp watch --provider azure
```
